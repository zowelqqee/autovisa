# Non-Stop Visa — Telegram-бот

Диалоговый бот юридического агентства **Non-Stop Visa** (релокация в Армению):
консультирует по услугам, собирает лиды и передаёт их менеджерам в групповой
чат, эскалирует сложные случаи и напоминает о себе клиентам, которые «зависли».
Понимает текст и голосовые сообщения.

**Стек:** Python 3.11+, python-telegram-bot 21 (async), OpenAI API
(`gpt-5.4-mini` + STT/TTS), SQLite (stdlib), APScheduler, python-dotenv.

Системных зависимостей нет — ffmpeg и прочие пакеты не требуются.

---

## Структура

```
bot/
  main.py            точка входа, конфиг, регистрация хендлеров, polling
  openai_client.py   чат-модель + SYSTEM_PROMPT (Responses API)
  voice.py           голосовые: распознавание (STT) и синтез (TTS)
  knowledge_base.py  услуги / FAQ / сроки как Python-структуры
  db.py              SQLite: users, conversations, leads, api_calls
  handlers.py        обработчики сообщений и команд Telegram
  usage.py           учёт запросов и токенов + опциональные лимиты
  followup.py        APScheduler: напоминания + уборка журнала
  preflight.py       проверка ключей и доступов перед запуском
  parser.py          теги [LEAD_CAPTURED] / [ESCALATE] + анти-инъекция
.env.example
requirements.txt
render.yaml          Blueprint для деплоя на Render (background worker + disk)
.python-version      версия Python для Render
```

### Как это работает

**Текст:**

1. Входящее сообщение проходит через `sanitize_user_input()` — подделать
   служебные теги нельзя.
2. Сообщение пишется в `conversations`, последние ~20 реплик + системный
   промпт с базой знаний уходят в модель.
3. Ответ разбирается `parse_model_response()`:
   - `[LEAD_CAPTURED]` → запись в `leads` + уведомление в `MANAGER_CHAT_ID`;
   - `[ESCALATE: причина]` → уведомление менеджеру с последними 5 сообщениями;
   - теги и markdown-разметка вырезаются, пользователю уходит чистый текст.
4. Если лид не закрыт и клиент молчит 6 часов — один follow-up
   «Остались вопросы? Я на связи».

**Голос** — те же шаги, обёрнутые в распознавание и синтез:

```
голосовое OGG/Opus  →  gpt-4o-mini-transcribe  →  та же чат-модель
                                                        ↓
Telegram voice  ←  gpt-4o-mini-tts (opus)  ←  текст без тегов
```

Два следствия этой схемы:

- **Теги работают и в голосе.** Чат-модель отвечает текстом, поэтому блок
  `[LEAD_CAPTURED]` вырезается *до* озвучки: клиент его не слышит, а лид
  фиксируется так же, как в переписке.
- **Перекодирования нет.** Telegram отдаёт Ogg/Opus, STT принимает его
  напрямую, TTS отдаёт Ogg/Opus обратно — ffmpeg не нужен.

Расшифровки обеих реплик пишутся в общую историю, поэтому клиент может
начать голосом и продолжить текстом без потери контекста.

## Роль агента

Агент работает **как сам менеджер**, а не как приёмщик заявок: ведёт клиента от
первого вопроса до понятного плана действий — какие услуги нужны, в каком
порядке, сроки, что подготовить.

Темы: законность пребывания, регистрация по адресу, социальный номер, ИП и
налоговые режимы, банковские счета и комплаенс, ВНЖ и ПМЖ, аренда жилья и
документы собственника, доверенности, визы.

### Процедуры независимы — главное правило

Регистрация ИП, открытие банковского счёта и регистрация по адресу — **три
отдельные процедуры**. Ни одна не является автоматическим условием другой.
В базе знаний намеренно нет «общего порядка действий»: любая такая
последовательность превращается в ложное правило.

Агент **не** отвечает шаблоном «сначала найдите адрес, потом откройте ИП,
после этого откройте счёт». Связывает процедуры только при конкретном
требовании: этот банк просит документы ИП, для этой миграционной процедуры
нужен адрес и т.п.

То же для статусов: **ВНЖ и ПМЖ — отдельные статусы со своими основаниями**.
Схема «ВНЖ → три года → ПМЖ» не используется: трёхлетнее проживание официально
входит в *семейное* основание ПМЖ, а не в предпринимательское и не в основание
по армянскому происхождению.

Проверено живьём:

```
КЛИЕНТ: Мне сказали, что сначала нужна прописка, потом ИП, потом счёт. Так?
АГЕНТ:  Нет, так не обязательно. Это три отдельные процедуры, они не являются
        автоматическим условием друг для друга...

КЛИЕНТ: У меня ИП, но ВНЖ нет. Могу подать сразу на ПМЖ по бизнесу?
АГЕНТ:  Трёх лет ВНЖ как общего правила для бизнеса нет: это требование
        официально связано с семейным основанием ПМЖ...
```

### Правила точности

Зашиты в промпт и в базу знаний:

- никаких гарантий результата — ни по счёту, ни по ВНЖ, ни по приёму договора;
- требование закона отделяется от внутренней практики банка или органа;
- сроки разделены на официальный, обычный, с учётом записи и при проблемах
  с документами;
- расходы маркируются категорией: госпошлина, нотариус, перевод, банковская
  комиссия, услуга сопровождения;
- цены и сроки называются вместе с датой актуальности (`KB_UPDATED`
  в [bot/knowledge_base.py](bot/knowledge_base.py));
- вопрос адреса разбирается отдельным блоком: дистанционно подписанный
  договор аренды могут не принять, это проверяется, а не обещается;
- фиктивная регистрация, фиктивный договор и обход комплаенса не предлагаются
  ни при каких формулировках запроса.

### Карточка клиента

Оба служебных тега — **внутренние**, клиент их не видит и о передаче не узнаёт.

`[LEAD_CAPTURED]` — карточка из 18 полей: имя, контакт, гражданство, город,
дата и документ въезда, статус пребывания, социальный номер, адрес, договор
аренды, доступность собственника, цель, услуги, срочность, проблемные места,
документы на руках, следующее действие, контекст. Модель заполняет только то,
что реально прозвучало; пустые поля в уведомление не попадают.

Карточка уходит вам в чат и сохраняется в БД: четыре основных поля — колонками
таблицы `leads`, остальные — JSON в колонке `card`. Агент при этом **не
прощается** и не пишет «с вами свяжутся» — консультация продолжается.

Без контакта карточка не создаётся: такой лид нерабочий и вдобавок отключил бы
follow-up.

`[ESCALATE]` не заменяет ответ: агент сначала отвечает сам, насколько может, и
параллельно помечает случай для вас. Список поводов:

| Случай |
|---|
| Итоговая цена, смета, скидка или цена того, чего нет в базе знаний |
| Оплата, договор, реквизиты |
| Нужно проверить оригиналы документов |
| Спор о праве собственности на жильё |
| Отказ банка |
| Нарушен срок пребывания, риск штрафа или выдворения |
| Нужно налоговое заключение или представительство по доверенности |
| Нестандартное гражданство или несколько гражданств |
| Сложно подтвердить источник средств |
| Деятельность связана с лицензированием |
| Клиент просит гарантировать результат |
| Клиент недоволен, жалуется, просит руководителя |
| Официальные источники противоречат друг другу |

Всё остальное агент ведёт сам. Роль и списки настраиваются в `SYSTEM_PROMPT`
в [bot/openai_client.py](bot/openai_client.py), фактура — в
[bot/knowledge_base.py](bot/knowledge_base.py).

### Услуги и цены

| Услуга | Сопровождение | Срок |
|---|---|---|
| ВНЖ (временный статус) | 1600 $ | рассмотрение до 30 дней |
| ПМЖ (постоянный статус) | 1600 $ | рассмотрение до 30 дней, карта на 5 лет |
| Гражданство | 1600 $ | зависит от основания |
| Регистрация по адресу | 500 $ | до 3 рабочих дней; по факту проживания — до 8 |
| Банковский счёт | 500 $ | 5–20 рабочих дней (KYC) |

| Социальная карта | 200 $ | 1–5 рабочих дней |
| Регистрация ИП | цену называет менеджер | регистрация сразу при подаче |

Суммы — стоимость сопровождения агентства. Отдельно, как другая категория
расходов, агент называет **государственные пошлины**:

| Пошлина | Размер |
|---|---|
| Регистрация ИП (бумажная подача) | 3 000 драмов |
| Регистрация по адресу | 1 000 драмов |
| Продление временной карты (до 1 года) | 105 000 драмов |
| Выдача/продление постоянной карты (5 лет) | 140 000 драмов |

Нотариус, переводы и банковские комиссии агент помечает как ещё одну категорию
и цифр по ним не называет — их подтверждает менеджер.

Все суммы и сроки называются вместе с датой актуальности `KB_UPDATED`.

## Выбор модели

Чат-модель по умолчанию — **`gpt-5.4-mini`** с `reasoning.effort=low`.
Выбрана замером на боевом промпте:

| Модель | Время ответа | Лид распознан | Расход |
|---|---|---|---|
| `gpt-5.5` (effort=low) | 3.9 с | да | 1672 вход / 94 выход |
| **`gpt-5.4-mini` (effort=low)** | **2.0 с** | **да** | 1672 вход / 120 выход |

Обе одинаково надёжно выдают служебные теги и держат сценарий, но для чат-бота,
работающего по чёткому скрипту, вдвое меньшая задержка важнее запаса интеллекта.
Модель меняется через `OPENAI_MODEL` без правки кода — если понадобится больше
глубины на сложных вопросах, поставьте `gpt-5.5` или поднимите `OPENAI_EFFORT`
до `medium`.

Голос: `gpt-4o-mini-transcribe` (распознавание, ~1.7 с) и `gpt-4o-mini-tts`
(синтез, ~1.4 с).

## Расход и лимиты

Жёстких квот на тарифе нет, поэтому **лимиты по умолчанию выключены**. Бот
всё равно ведёт журнал обращений в таблице `api_calls` — это нужно, чтобы
видеть реальное потребление:

- команда `/stats` в чате менеджеров показывает запросы и токены за сутки;
- в логах каждая реплика сопровождается строкой с расходом токенов.

Один ход диалога — около **9800 токенов**: системный промпт с базой знаний
занимает ~9500 и одинаков в каждом запросе. Работает автоматическое
кэширование OpenAI — из кэша приходит **~96% входных токенов**, поэтому
реальная стоимость заметно ниже номинала.

Дата актуальности дописывается в конец инструкции именно ради этого: если
поставить её в начало, меняющийся префикс обнулял бы кэш каждый день.

Если понадобится подстраховаться от неожиданного счёта, включите лимиты
в `.env` — тогда запрос отсекается **до** отправки, а не ловится по 429:

```bash
OPENAI_RPM=20        # запросов в минуту
OPENAI_RPD=500       # запросов в сутки
OPENAI_TPD=1000000   # токенов в сутки
```

Ноль означает «без ограничения». Счётчики лежат в SQLite, поэтому перезапуск
сервиса их не обнуляет.

## Шаг 1. Установка

```bash
git clone <ваш-репозиторий> autovisa && cd autovisa
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt
```

## Шаг 2. Настройка `.env`

```bash
cp .env.example .env
```

Заполните три обязательных значения:

| Переменная | Где взять |
|---|---|
| `TELEGRAM_BOT_TOKEN` | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `OPENAI_API_KEY` | https://platform.openai.com/api-keys |
| `MANAGER_CHAT_ID` | ID группового чата менеджеров — см. Шаг 3 |

Токены нигде не хардкодятся — только через `.env` (файл в репозиторий
**не коммитить**).

## Шаг 3. Как получить `chat_id` группы менеджеров

`MANAGER_CHAT_ID` — это ID **группового** чата, не личка.

1. Создайте группу и добавьте туда бота как участника.
2. Убедитесь, что у бота есть право отправлять сообщения. Если группа —
   супергруппа с ограничениями, выдайте боту права администратора.
3. Отправьте в группу любое сообщение (например, `/start@your_bot`).
4. Дёрните `getUpdates`:

```bash
curl "https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates"
```

5. В ответе найдите объект чата и возьмите `id`:

```json
{"message": {"chat": {"id": -1001234567890, "title": "Non-Stop Visa — лиды", "type": "supergroup"}}}
```

Скопируйте это значение в `MANAGER_CHAT_ID`.

> **Важно:** у групп ID **отрицательный**. У супергрупп он начинается
> с `-100` (например `-1001234567890`) — минус и префикс `-100` обязательны.
> Если `getUpdates` возвращает пустой `result`, отправьте сообщение в группу
> ещё раз: Telegram отдаёт только новые апдейты. Также getUpdates не работает,
> пока запущен бот в режиме polling — сначала остановите сервис.

## Шаг 4. System-промпт

Промпт лежит в константе `SYSTEM_PROMPT` в
[bot/openai_client.py](bot/openai_client.py) и уже заполнен. Правится там же.

Промпт **обязан** описывать модели формат служебных тегов, иначе парсер лидов
и эскалаций не сработает:

```
[LEAD_CAPTURED]
name: <имя>
contact: <телефон / @username / email>
service: <услуга>
context: <ситуация клиента в 1–2 предложениях>
[/LEAD_CAPTURED]

[ESCALATE: <краткая причина>]
```

База знаний (услуги, сроки, FAQ) подмешивается автоматически из
`bot/knowledge_base.py` — дублировать её в промпте не нужно. Проверить,
как она выглядит для модели:

```bash
python -m bot.knowledge_base
```

## Шаг 5. Миграция БД

Отдельной команды не требуется: `db.init_db()` выполняется при старте и
создаёт таблицы `users`, `conversations`, `leads`, `api_calls`, если их нет.
Недостающие колонки в уже существующих таблицах досоздаются там же
(`_migrate()`), поэтому обновление на новую версию не требует ручных действий.

Файл БД — `autovisa.db` в рабочем каталоге, путь переопределяется
переменной `DB_PATH`.

Создать БД заранее (например, чтобы проверить права на каталог):

```bash
python -c "import asyncio; from bot import db; asyncio.run(db.init_db())"
```

Бэкап на живом боте (WAL включён, останавливать сервис не нужно):

```bash
sqlite3 autovisa.db ".backup '/var/backups/autovisa-$(date +%F).db'"
```

Полезные запросы:

```bash
sqlite3 autovisa.db "SELECT COUNT(*) FROM leads;"
sqlite3 autovisa.db "SELECT created_at, name, contact, service FROM leads ORDER BY id DESC LIMIT 10;"
# расход за сутки
sqlite3 autovisa.db "SELECT COUNT(*), SUM(tokens) FROM api_calls WHERE created_at > datetime('now','-1 day');"
```

## Шаг 6. Предполётная проверка

Перед первым запуском (и после любой правки `.env`):

```bash
python -m bot.preflight
```

Проверит ключи, доступность моделей, валидность токена и то, что бот
действительно состоит в чате менеджеров. Ничего никуда не отправляет —
все вызовы читающие. Типичные находки:

| Вывод | Что делать |
|---|---|
| `токен отклонён Telegram (Unauthorized)` | Токен неверен или отозван — возьмите актуальный в @BotFather |
| `чат ... недоступен` | Бот не добавлен в группу, или в `MANAGER_CHAT_ID` осталась заглушка из `.env.example` |
| `MANAGER_CHAT_ID ... положительный` | Это ID лички, нужен ID группы (отрицательный) |
| `чат-модель ... недоступна` | Модель не открыта на вашем ключе — смените `OPENAI_MODEL` |

## Шаг 7. Запуск

```bash
python -m bot.main
```

В логах должно появиться `Бот запущен: @your_bot`. Напишите боту в личку
или отправьте голосовое — ответит в том же формате.

## Деплой на Render

Бот работает в режиме polling, поэтому на Render это **Background Worker**,
а не Web Service: входящих HTTP-запросов у него нет, порт слушать не нужно.
В репозитории есть готовый [render.yaml](render.yaml) — Blueprint, который
создаёт сервис с нужными настройками.

### Что важно знать заранее

**Free-тариф для этого бота не подходит.** Две независимые причины:

| Ограничение | Последствие |
|---|---|
| Background Worker недоступен на free — только со Starter | Воркер требует платного плана |
| Free web service Render усыпляет после 15 минут без входящего трафика | Бот перестаёт отвечать |
| Persistent disk доступен только на платных планах | Без диска БД стирается |

**Persistent disk обязателен.** Файловая система Render эфемерная: при каждом
деплое и рестарте все локальные файлы теряются. Без диска при первом же
обновлении кода исчезнут лиды, история диалогов, флаги follow-up и журнал
расхода. В `render.yaml` диск монтируется в `/var/data`, туда же указывает
`DB_PATH`.

**Только один инстанс.** Telegram допускает одно соединение `getUpdates` на
токен — второй инстанс вызовет `Conflict: terminated by other getUpdates
request`. Подключённый диск и так запрещает масштабирование, но автоскейлинг
для этого сервиса включать нельзя.

Минимальная конфигурация: план **Starter** (512 МБ RAM, 0.5 CPU) — боту этого
хватает с запасом — плюс диск на 1 ГБ.

### Шаги

1. Залейте проект в репозиторий на GitHub или GitLab (файл `.env` не
   коммитить — он в `.gitignore`).

2. В Render: **New → Blueprint** → выберите репозиторий. Render прочитает
   `render.yaml` и покажет, что собирается создать.

3. Render запросит три секрета (в `render.yaml` они помечены `sync: false`,
   поэтому в репозиторий не попадают):

   - `TELEGRAM_BOT_TOKEN`
   - `OPENAI_API_KEY`
   - `MANAGER_CHAT_ID`

4. Нажмите **Apply**. Первая сборка — установка зависимостей из
   `requirements.txt`, затем запуск `python -m bot.main`.

5. Откройте **Logs**. Должно появиться:

   ```
   База данных инициализирована: /var/data/autovisa.db
   OpenAI готов: model=gpt-5.4-mini effort=low
   Голосовой режим готов: gpt-4o-mini-transcribe -> gpt-4o-mini-tts
   Бот запущен: @your_bot
   ```

   Путь `/var/data/...` в первой строке — подтверждение, что БД лежит на
   диске, а не в эфемерной файловой системе.

### Настройки в render.yaml

| Параметр | Значение | Почему |
|---|---|---|
| `type` | `worker` | Polling, входящего трафика нет |
| `plan` | `starter` | Самый дешёвый платный; free для воркеров нет |
| `region` | `frankfurt` | Ближайший к Армении из доступных (ещё: oregon, ohio, virginia, singapore) |
| `disk.mountPath` | `/var/data` | Диск для SQLite |
| `DB_PATH` | `/var/data/autovisa.db` | БД на диске, переживает деплой |
| `.python-version` | `3.13` | Версия, на которой проект протестирован |

Модель, глубину рассуждений, голосовой режим и уровень логов можно менять в
Dashboard → Environment без правки кода.

### Обновление и остановка

Деплой при пуше в основную ветку включён (`autoDeploy: true`). При деплое
Render присылает процессу SIGTERM — python-telegram-bot перехватывает его,
корректно останавливает polling и закрывает соединение с БД, поэтому SQLite
не остаётся в незакрытом состоянии.

Поставить бота на паузу: **Settings → Suspend Service**. Диск при этом
сохраняется.

### Бэкап БД

Диск не бэкапится сам. Скачать базу можно через **Shell** в Dashboard:

```bash
sqlite3 /var/data/autovisa.db ".backup '/var/data/backup.db'"
```

Либо периодически выгружать лиды в чат менеджеров — если это нужно, скажите,
добавлю команду `/export`.

## Деплой на VPS (Ubuntu)

### Подготовка

```bash
sudo apt update && sudo apt install -y python3-venv python3-pip sqlite3 git
sudo useradd -r -m -d /opt/autovisa -s /usr/sbin/nologin autovisa

sudo -u autovisa git clone <ваш-репозиторий> /opt/autovisa/app
cd /opt/autovisa/app
sudo -u autovisa python3 -m venv /opt/autovisa/venv
sudo -u autovisa /opt/autovisa/venv/bin/pip install -r requirements.txt

sudo -u autovisa cp .env.example .env
sudo -u autovisa nano .env          # заполнить токены
sudo chmod 600 .env                  # секреты читает только владелец
```

### systemd unit

`/etc/systemd/system/bot.service`:

```ini
[Unit]
Description=Non-Stop Visa Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=autovisa
Group=autovisa
WorkingDirectory=/opt/autovisa/app
EnvironmentFile=/opt/autovisa/app/.env
ExecStart=/opt/autovisa/venv/bin/python -m bot.main

# Автоперезапуск при падении
Restart=always
RestartSec=10
# Не уходить в бесконечный цикл рестартов при сломанном конфиге
StartLimitIntervalSec=300
StartLimitBurst=5

# Логи в journald
StandardOutput=journal
StandardError=journal
SyslogIdentifier=autovisa-bot

# Базовое ужесточение
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now bot.service
sudo systemctl status bot.service
sudo journalctl -u bot.service -f          # живые логи
sudo systemctl restart bot.service         # после правки .env или промпта
```

> `EnvironmentFile` не поддерживает кавычки и подстановки — пишите значения
> как `KEY=value` без кавычек. `load_dotenv()` в коде остаётся для локальной
> разработки; в systemd переменные приходят из `EnvironmentFile`.

### Режим polling

Бот работает через **polling** (`getUpdates`) — домен, статический IP и
SSL-сертификат не нужны. Одно ограничение: **одновременно может быть запущен
только один экземпляр** бота с этим токеном, иначе Telegram вернёт
`Conflict: terminated by other getUpdates request`. Перед ручным запуском
остановите сервис: `sudo systemctl stop bot.service`.

Переход на webhook имеет смысл при высокой нагрузке и уже имеющемся домене
с HTTPS — на старте не требуется.

### Прокси (если IP VPS заблокирован по региону)

По умолчанию прокси **выключен**. Включается переменными в `.env`:

```bash
TELEGRAM_PROXY_URL=http://user:pass@1.2.3.4:8080     # или socks5://...
OPENAI_PROXY_URL=http://user:pass@1.2.3.4:8080
```

Можно задать только один из них — например, если блокируется только
OpenAI API. Вместо `OPENAI_PROXY_URL` допустима стандартная переменная
`HTTPS_PROXY`: httpx подхватит её автоматически.

Для SOCKS5 нужен дополнительный пакет:

```bash
pip install "httpx[socks]"
```

Проверка доступности с VPS:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://api.telegram.org
curl -s -o /dev/null -w "%{http_code}\n" https://api.openai.com
```

## Диагностика

| Симптом | Причина и что делать |
|---|---|
| `Не задана обязательная переменная окружения ...` | Незаполненный `.env` или `EnvironmentFile` |
| `Conflict: terminated by other getUpdates request` | Запущено два экземпляра бота — остановите лишний |
| Лиды не приходят в группу | Проверьте `MANAGER_CHAT_ID` (минус и `-100`), бот добавлен в группу и может писать |
| Пользователь получает fallback-сообщение | OpenAI недоступен после всех ретраев — смотрите `WARNING`/`ERROR` в логах |
| «Не получилось разобрать голосовое» | Смотрите лог: пустая запись, слишком большой файл (>20 МБ) или ошибка STT |
| Бот просит писать текстом вместо ответа голосом | `VOICE_ENABLED=0` в окружении |
| Ответ обрывается на полуслове | Увеличьте `OPENAI_MAX_OUTPUT_TOKENS` |
| Ответы слишком поверхностные | Поднимите `OPENAI_EFFORT` до `medium` или смените `OPENAI_MODEL` на `gpt-5.5` |
| Follow-up не приходит | Он один на «зависание»; повторно возможен только после нового сообщения клиента. Проверьте `SELECT followup_sent FROM users WHERE user_id=...` |
